# Memory Leak Observations

In this assignment, I learned that a memory leak happens when a program allocates memory but does not release it when it is finished using it. In the memory leak demonstration, memory was allocated inside the loop using malloc(1000 * sizeof(int)). The loop ran 1000 times, but there was no free() call inside the loop. This meant that every time the loop repeated, another block of memory was allocated without the previous block being released. When I ran the program, it showed that about 3,906 KB of memory was leaked. If this same code continued running repeatedly, the amount of memory being wasted would continue to increase. In a server application running for days, this could eventually cause the program to use a large amount of RAM or just crash. This showed me why even a small memory leak can become a much bigger problem when a program runs for a long time.

In the fixed version, I added free(temp_item); inside the loop after the allocated memory was used. This releases the memory during every iteration instead of leaving it allocated. The program still allocated about 3,906 KB throughout the loop, but that memory was also freed and could be reused. I learned that when using malloc() in C, I have to make sure the memory is eventually matched with a free() call when it is no longer needed.

# Python vs C Memory Management

One of the biggest differences I noticed between Python and C is how much more involved memory management is in C. In Python, I can create a list with inventory = [] and add items without deciding how much more memory needs to be allocated. In C, I had to manually allocate memory using malloc(), check if it succeeded by comparing the pointer to NULL, and then use realloc() when the inventory needed more space. I also had to keep track of the pointers to the allocated memory and call free() when I was done using it. After freeing a pointer, I had to set it to NULL and check it before trying to use it again. Python usually handles most of the tasks automatically. 

Behind the scenes, Python managed memory mainly through reference counting along with a garbage collector. Python keeps track of how many references point to an object. When an object is no longer being used and its reference count reaches zero, Python can release the memory that was being used by that object. Python's garbage collector also helps finds groups of objects that reference each other but are no longer accessible by the program. This is useful because reference counting alone may not recognize that this memory is no longer needed. 

# Garbage Collection Trade-offs

Python's garbage collection makes memory management much easier for the programmer, but it still requires extra work from the computer. Python has to keep track of objects and their references to figure out when memory is no longer being used. Doing this takes some extra memory and processing power. For most programs, this is helpful because the programmer does not have to worry as much about managing memory themselves. However, I can understand why someone programming an operating system or an embedded device would choose C. C gives the programmer more control over exactly when memory is allocated and freed. This can make the program more efficient, but it also means the programmer has to be more careful because mistakes can cause memory leaks or crashes.
